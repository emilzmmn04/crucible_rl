crucible_rl v0.1

An environment runtime for agentic reinforcement learning of small open models.

Status: pre-alpha, design phase  ·  License: Apache-2.0 (core)  ·  Languages: Rust, Python

Abstract. Training algorithms for LLM reinforcement learning (GRPO, PPO, RLOO) are well served by existing trainers. The bottleneck for agentic RL is elsewhere: running thousands of multi-step, tool-using episodes in isolated sandboxes, scoring them with tamper-proof verifiers, and delivering token-exact trajectories to the trainer without stalling the GPU. crucible_rl is a Rust runtime for exactly that layer — environments, rollouts, rewards, trajectories — with a Gym-like Python API on top and pluggable trainer backends below.

01Thesis

We do not reimplement the optimizer. We make the loop around it fast, reproducible and easy.

policy  +  environment  +  verifier  +  config   →   a better agent
  • Environment-first. The unit of work is an episode, not a prompt.
  • Asynchronous by default. One slow pytest never blocks 1,023 other episodes.
  • Verifiable rewards. Verifiers run outside the agent's sandbox; the agent never sees answers or grader code.
  • Token-exact. Trajectories keep token IDs, logprobs, loss masks and policy version — no re-tokenization drift.
  • One GPU is a first-class target. A 4B model + LoRA on a single 24 GB card must work out of the box.

02Interface

Define an environment

import crucible_rl as crl

class FixTests(crl.Env):
    sandbox = crl.Docker("python:3.12-slim")
    tools   = [crl.tools.shell, crl.tools.edit_file]
    max_turns = 24

    async def reset(self, task):
        await self.sandbox.checkout(task.repo, task.commit)
        return f"Make the failing tests pass: {task.issue}"

    @crl.verifier(isolated=True)
    async def reward(self, sb, task):
        r = await sb.run("pytest -q", timeout=120)
        return 1.0 if r.exit_code == 0 else r.passed / r.total

Fig. 1 — Proposed API. Tools, sandbox and verifier are declarative; the runtime owns the loop.

Train

$ crl train \
    --model  Qwen/Qwen3-4B \
    --env    ./envs/fix_tests.py --tasks swe-mini.jsonl \
    --algo   grpo --group-size 8 --lora-rank 32 \
    --gpus   1

Low-level, Gymnasium-compatible

env = crl.make("terminal/fix-tests-v1", num_envs=256)

async for ev in env.events():                  # no global step barrier
    if ev.kind == "observation":
        await env.submit(ev.env_id, await policy(ev.obs))
    elif ev.kind == "done":
        trainer.push(ev.trajectory)            # tokens, logprobs, masks, reward

Fig. 2 — Event-driven vector env. A synchronous reset()/step() wrapper exists for debugging.

06Open questions

  1. Bring-your-own-trainer only, or ship a minimal GRPO trainer for the single-GPU path?
  2. Off-policy tolerance: how many policy versions may a rollout lag before discard or importance-correction?
  3. Reward hacking: which canaries and audits are built in by default?
  4. Open-core boundary: is managed cloud sandboxing the closed part?
